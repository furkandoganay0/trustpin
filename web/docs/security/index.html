Security

Security model

TrustPin is designed for zero‑trust environments. Every approval must be cryptographically verifiable.

Public‑key only storage

Devices generate Ed25519 keypairs locally. The server stores only public keys, limiting the impact of a server compromise.

Canonical payloads

Approvals use deterministic payload ordering to prevent signature confusion and replay attacks.

Nonce uniqueness + TTLs

Each challenge includes a unique nonce. Redis enforces uniqueness until expiration.

Guarantee

Even with database access, an attacker cannot approve without the device signature.

Audit log

All state transitions produce append‑only audit events, enabling forensic timelines and compliance review.
