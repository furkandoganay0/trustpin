Introduction

TrustPin – Bank‑grade mobile approval & MFA backend

TrustPin is a security‑first, on‑prem deployable approval system. It does not authenticate users; it only verifies cryptographic approval for sensitive actions. Built for banks, fintechs, and enterprises, TrustPin is open‑source and self‑hostable.

What TrustPin is

A cryptographic approval backend with strict state machines, append‑only audit trails, and device‑signed challenges.

What TrustPin is not

TrustPin does not replace your identity provider or authentication stack. It assumes identity is handled elsewhere and focuses solely on secure approvals.

Key concepts

TrustPin relies on deterministic payloads and signed challenges to guarantee verifiable approvals. The server stores only public keys, and every approval is validated against a canonical JSON payload.

// Canonical payload fields (ordered) { tenant_id, user_id, device_id, challenge_id, nonce, action, issued_at, expires_at, context_hash }

High‑level architecture

The API service runs statelessly and relies on PostgreSQL for source‑of‑truth state, Redis for TTL caches and nonce uniqueness, and a push provider for notifying devices.

  • API service (Go) with strict HTTP handlers
  • PostgreSQL for state machines and audit log
  • Redis for TTL caches, rate limits, and nonce uniqueness
  • Push provider abstraction (mockable)

Typical flow

Enrollment → Device activation → Challenge initiation → Approve/Reject → Audit event. Each transition is validated and recorded.
